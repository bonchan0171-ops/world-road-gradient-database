# アーキテクチャ概要

World Road Gradient Database (WRGD) は、長期的な地理空間データエンジニアリングプラットフォームとして設計されています。アーキテクチャは、大規模な道路ネットワークと標高処理において、モジュール性、保守性、プロビナンス（履歴管理）を重視します。

## コア原則

- 関心の分離: 取得、処理、保存、表示を明確に分ける。
- データ契約: 各パイプライン段階の入力と出力を定義する。
- 拡張性: コアロジックを変更せずに新しい DEM ソース、道路属性、エクスポート形式を追加できる。
- 再現性: 生データ入力と処理メタデータを保存し、監査可能性を確保する。

## レイヤー

### 1. データ取得

このレイヤーは、OpenStreetMap、JAXA AW3D30、NASA SRTM、Copernicus DEM のソースアダプターを扱います。各アダプターの責務は以下です。

- 公式データセットまたは API へのアクセス
- 生データファイルのダウンロードまたは参照
- ソースメタデータとライセンスの検証
- 外部形式を一貫した内部表現に変換する

### 2. ドメイン処理

このレイヤーは、道路ネットワークと標高解析の概念を含みます。

- 道路セグメントの抽出
- ジオメトリに沿った標高サンプリング
- 勾配および曲率の計算
- 長さ、上昇/下降、最大勾配などの集計指標

ドメインレイヤーは外部 I/O ロジックを含まず、構造化データオブジェクトで動作すべきです。

### 3. インフラストラクチャ

インフラ層は、保存、変換、外部ツール統合を実装します。

- 生データ保存
- 処理済みタイルおよびベクトル保存
- キャッシュ
- 形式変換 (GeoPackage、Parquet、Cloud-optimized GeoTIFF)

このレイヤーは、GDAL、Rasterio、PostGIS などの GIS 固有の統合も担当します。

### 4. インターフェースとオーケストレーション

このレイヤーは、エンドツーエンドのワークフローと実験をオーケストレーションします。

- データセット組み立て用スクリプト
- 探索的分析のためのノートブック
- リサーチノートとドキュメント
- 将来の API や展開メカニズム

## データフロー

1. OpenStreetMap から道路ジオメトリを取得する。
2. DEM ソースから標高面を取得する。
3. 空間参照変換を介して道路ジオメトリを標高データに整列させる。
4. セグメントごとの標高、平均および最大勾配、曲率を計算する。
5. プロビナンスメタデータとともに生データおよび処理済みデータディレクトリに出力を保存する。

## プロジェクト構成

- `data/`: 生データおよび処理済みデータの保存。
- `src/`: 将来の実装モジュール。
- `notebooks/`: 探索的分析および例。
- `scripts/`: ワークフローのオーケストレーションと自動化。
- `docs/`: 技術設計、アーキテクチャ、ロードマップ。
- `research/`: データセット調査、文献、計画。

## 進化

このクリーンアーキテクチャは、次をサポートします。

- コアロジックを再設計せずにデータセットを追加できる。
- 新しい道路属性やメタデータソースを追加できる。
- 後のフェーズで機械学習や AI アプリケーションを導入できる。
- ローカルなリサーチプロトタイプを維持しつつ、グローバル規模の本番データセットをサポートできる。
